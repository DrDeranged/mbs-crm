## Repairs made in this workspace

1. **Mobile offline reliability:** hydrate persisted mutations before replay; attempt replay when already online after launch; serialize storage writes so enqueue/removal cannot overwrite each other; retain failed mutations. New entries are bound to their Clerk owner, and another account or a legacy ownerless entry cannot replay under the wrong identity. Blocked entries remain on device and are explained in the banner; the app does not silently delete them. Tokenless replay is prohibited.
2. **Mobile creation and sign-in:** make sign-in scroll around the keyboard; accept only the two lead-create financing types supported by the API; validate and submit optional whole-dollar `requestedAmount` for both online and offline paths; use the API's actual `existing_lead_id` field when surfacing duplicates. The OpenAPI contract and generated client/Zod parser were regenerated; the existing lead database column stores the amount.
3. **Web browser safety and small screens:** sanitize stored HTML with DOMPurify before showing email template/lead communication previews; keep intended formatting and safe links. Allow lead-document actions to wrap on narrow screens.
4. **Post-merge setup:** the previous run reached the schema guard and was killed by its 20-second limit. Raised the configured limit to 90 seconds, reran the same install/migration/guard script successfully; migration reported zero new changes and the schema-path guard passed.
5. **Clean-install validation:** the first full preflight reached its migration rehearsal, where database schema CI tests could not resolve the undeclared `drizzle-kit` dependency after a clean install. Declared version `0.31.10` in the database workspace package; its focused seven schema-CI tests then passed. No database migration or production data was changed to address this.

## Remaining risk / release gates

1. **Deployment mismatch:** do not infer that the public site contains these fixes. Verify a new public API revision header and web assets after an explicitly authorized publish; no publish was done here.
2. **SSN submission configuration:** application intake calls SSN encryption and can throw if its configured key is missing or invalid. Existing proposed work to guard this path remains open. No synthetic SSN submission or production secret inspection was done.
3. **Mobile offline conflicts and legacy entries:** a queued HTTP 409 still warns and discards the operation; a previous owner's legacy ownerless operation is intentionally quarantined rather than incorrectly replayed. A review/recovery workflow and device-level replay tests remain necessary.
   The mobile lead detail also logs call/SMS attempts without confirming the phone app opened, and SMS uses a call-activity path; these were traced but not exercised or repaired here.
4. **Authenticated end-to-end gaps:** least-privilege rep/manager/admin synthetic accounts and isolated fixtures are needed for UI→API→database checks across leads, deals, documents, governance and notifications. Signed Twilio/SendGrid callbacks and delivery must use controlled test destinations and cannot be certified from route inspection.
5. **Observed deployment auth noise:** sampled published logs contained repeated Clerk proxy upstream 401 errors at about 14:59 UTC, while later token requests returned 200. Without a user-session reproduction this is not evidence that all logins are failing.

The report does not claim all routes work or that production is ready. It records what was directly observed, what was locally tested, and where further controlled verification is required.
